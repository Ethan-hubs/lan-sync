4. 发现的问题（分级，均不影响本轮通过）

P1-1 · 全部工程 TFM 都是 net10.0-windows，Linux/CI 无法构建 LanSync.Core、LanSync.Syncthing 与两个测试工程都不含 Windows API 依赖（唯一 Windows 分支在测试的 LongPath 辅助类里），却继承了 -windows TFM。后果：任何 Linux/macOS CI 或第三方复核都必须先改副本（我这次就是）。建议：库与测试改 net10.0，只有将来托盘工程保留 net10.0-windows + SupportedOSPlatformVersion。改完我方即可全自动复核（git clone + 环境变量 + dotnet test），不再需要人工改动。 注：这也符合"不要无谓抬高 OS 门槛"的同一逻辑——库不需要 Windows 目标框架。

P1-2 · 自建实例模式把 Windows 二进制哈希写死 SyncthingPair.RequiredWindowsSha256 是常量，非 Windows 上自建模式必然失败。建议按 OS 选择期望值，或支持 LANSW_SYNCTHING_SHA256 覆盖（我已备好 Linux 值 ab0ea5f3…4ce07f，官方 v2.1.5 linux-amd64 解包二进制）。

P1-3 · C5 用全局 /rest/system/pause 全局暂停会连带暂停该实例上其它 folder —— 对"共享实例"场景有副作用。建议契约测试优先用按设备暂停（?device=），或在测试文档里明确"集成实例必须专用"。真正的"恢复事务暂停范围"规则（只暂停本次需要、原先非 paused 的对端，finally 只恢复该集合）属于下一迭代 C7。

P2-4 · GetConnectionsAsync 对非法 device 键会整表失败 new DeviceId(key) 校验 8 段，遇到非标准键会抛异常导致整次调用失败。建议跳过并记录，而不是整表抛。

P2-5 · 外部实例模式下会残留 device 条目 folder 配置已正确清理，但 AddDeviceAsync 加的设备条目留在实例上（自建模式整实例销毁，无影响；外部模式会累积）。建议清理或至少在报告里注明。

P2-6 · 缺 src/ 的使用说明 仓库根 README 是"设计与工具仓库"那份。建议补一页：SDK 版本（10.0.401）、四个 LANSW_TEST_* 变量与 LANSW_SYNCTHING_BIN、skip 语义、dotnet test 期望结果。

P2-7 · 未覆盖 C7 恢复事务（按迭代 1 范围属预期，不算缺陷，列此备忘）
