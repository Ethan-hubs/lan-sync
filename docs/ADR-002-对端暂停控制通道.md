# ADR-002 · 恢复事务的「对端暂停」控制通道（LAN 控制端点）

- 状态：**已定稿 · 不排期**（2026-09-20 项目发起人决策：阶段一正式形态＝降级语义；本 ADR 记档为 M1 之后候选）
- 决策者：主线（hermes 本机线）
- 适用：`src/LanSync.Core`、`src/LanSync.Syncthing`、`src/LanSync.Tray`、`deploy/`
- 前置事实：ADR-001 §11（托盘↔Adapter 接口边界）、PRD §6.8（冲突与恢复）、
  `docs/G1-Adapter接口约定.md` §6（恢复三步事务）、`adapter/exp_restore.py`（对照实验）

---

## 1. 问题（为什么需要这份 ADR）

恢复历史版本**必须**先把会覆盖它的对端暂停，否则对端会在 1–2 秒内把旧内容推回来，
而 API 仍然返回成功——这是实测出来的静默数据覆盖（`adapter/exp_restore.py` 对照实验，
并已固化成契约测试 `C7_negative_restore_without_pausing_peer_is_overwritten`）。

C7 的实现要求：`pause(对端) → POST /rest/folder/versions → 校验响应字典为空 → resume(对端)`，
其中"暂停对端"要通过**对端引擎自己的 REST** 完成（`/rest/device/<id>/pause`）。

**但阶段一没有任何到达对端引擎的通道**：引擎只监听 `127.0.0.1:8384`（ADR-001 §5），
我们也没有自研信令/控制通道。⇒ 托盘点"恢复版本"时拿不到对端 Adapter。

## 2. 已落地的处理（迭代 2.1，`14a8b76`）：降级恢复

`RestoreVersionAsync(..., IReadOnlyDictionary<DeviceId, SyncthingAdapter>? peerAdapters = null, ...)`

- `peerAdapters` 可空；缺失某台对端的适配器时**不再抛异常**，改为记入
  `VersionRestoreResult.UnpausedDevices` 并继续；
- 返回值新增 `PeerPaused: bool`（= 所有共享该文件夹的对端都被成功暂停）与 `UnpausedDevices`；
- 有通道时仍是**强保证**（C7 正例/负例语义不变，且新增断言 `PeerPaused=true`、`UnpausedDevices` 为空）；
- 无通道时**跳过"等恢复文件被重新索引"**（对端未暂停时该等待没有意义），
  由 UI 明示风险："对端在线时可能产生冲突副本"。

这样托盘可以解锁恢复面板，**代价是暴露风险而不是隐藏风险**——这是产品上的取舍，写进 UI 文案。

## 3. 决策

1. **阶段一交付降级语义**（已实现，本轮并入 main）：恢复面板可用，语义务必如实上报。
2. **控制通道另立本合同**：作为**阶段二**能力，排期在 M1 之后；阶段一**不写第四样自研件**
   （PRD §2.7 的"只自研三样"原则仍成立）。
3. 控制通道**只服务"暂停/恢复对端"这一件事**，不做通用远程控制面。

## 4. 控制通道设计（阶段二实现依据）

### 4.1 传输与身份：复用引擎既有密钥，不新建 PKI

| 项 | 决定 |
|---|---|
| 端点 | 每台设备在**局域网接口**上监听 `https://0.0.0.0:22001`（仅 LAN 可达；不放公网） |
| 证书 | **复用引擎已有的 `cert.pem` / `key.pem`**（ADR-001 §10：卸载保留该两件即保持 Device ID）。身份 = Syncthing Device ID，无需新发证书 |
| 双向认证 | mTLS + 校验对端证书指纹 == 已知 Device ID。对端必须在**本机 Syncthing 配置里已存在**（即已互加设备）才接受 |
| 禁止 | 不复用 `strelaysrv` 通道（中继只转发同步协议流量，不承载任意 TCP）；不新增公网端口 |

### 4.2 协议（只两个维护动作 + 一个探活）

```
POST /v1/pause     body: {"device": "<发起方 Device ID>", "folder": "<folderId>", "reason": "<文本≤200>"}
POST /v1/resume    body: {"device": "<发起方 Device ID>", "folder": "<folderId>"}
GET  /v1/health    → {"ok": true, "device": "<本机 Device ID>", "pausedFor": ["<device>", ...]}
```

- **授权**：仅当 ① 对端证书指纹在设备列表里；② `device` 字段 == 请求方自身 Device ID（不得代人暂停别人）；
  ③ `folder` 与本机某文件夹 ID 匹配且该请求方共享该文件夹；④ 动作只能是 pause/resume。任一不满足 → 403。
- **幂等**：重复 pause 同一 `device` 返回 200（已暂停）；`resume` 对未暂停对象同样 200。
- **租约与自愈**：pause 带 `leaseSeconds`（默认 120，上限 600）。到期或进程重启后**自动恢复**——
  防止发起方崩溃把对端永久留在暂停态（这是本设计里最关键的安全阀）。
- **限流与审计**：每设备 ≤ 6 次/分钟；所有动作写 `%ProgramData%\LanSync\logs\control.log`。

### 4.3 发现与可达性

- 地址来源：复用 Syncthing 自己的连接信息（`/rest/system/connections` 里的对端地址），
  不新发明发现协议、不新增 mDNS 服务；
- **只做 LAN**：经中继/纯公网的对端拿不到控制通道 → 自动回落到 §2 的降级语义；
- 控制通道不可达**不得**阻断恢复流程（超时 ≤ 2 s 即放弃并记入 `UnpausedDevices`）。

### 4.4 与 Adapter 的接口

- 新增 `ILanControlChannel`（`src/LanSync.Syncthing`，默认实现 `NoopControlChannel`）；
- `RestoreVersionAsync` 的 `peerAdapters` 参数**保持不变**（不破坏已有签名与测试）：
  由上层用"控制通道 → 对端 Adapter"的适配器装配出字典再传入，
  这样降级路径与强路径**共用同一套事务代码**，不会出现两套语义。

## 5. 为什么不选另两条路（留痕）

| 方案 | 结论 | 理由 |
|---|---|---|
| ① LAN 控制通道（本合同） | 阶段二做 | 体验最好、能力真实，但属第四样自研，会破坏阶段一的"三样"边界 |
| ② 半自动：提示用户去对端点暂停 | 不采 | 零新组件但 3–5 人团队里必然被忽略，风险回到"静默覆盖" |
| ③ 可选参数降级（已实现） | 阶段一采用 | 库侧改动小、解锁面板、风险显式暴露；与①兼容（同一签名） |

## 6. 验收（阶段二开工时按此验收）

1. 两台真机（或同机双实例）+ 仅 LAN：pause→restore→resume 全流程后 `PeerPaused=true`；
2. **租约自愈**：pause 后杀掉发起方进程，对端 ≤ 租约时间自动恢复，且 `control.log` 有记录；
3. **越权**：伪造/未互加的 Device ID 请求 → 403，且本机文件夹状态不变（负例必须实跑）；
4. **不可达**：拔网线/关对端 → 恢复仍成功，结果里 `UnpausedDevices` 非空，UI 出现风险提示；
5. 端口 `22001` **不放公网**（云安全组不开）；本机防火墙限制为局域网网段。

## 7. 决策留痕（2026-09-20 已定）

项目发起人口径：**"先按照能跑的标准来"** ⇒
1. **控制通道不排期**：阶段一正式形态＝本 ADR §2 的降级语义；本 ADR 转为 **M1 之后候选**，恢复面板不因它阻塞；
2. 若将来启用：端口 `22001`、租约 120 s 沿用 §4 的设计（复用引擎证书做 mTLS、租约自愈、越权负例验收）；
3. 触发条件（届时重新评估）：真实使用中出现因"对端未暂停"导致的冲突副本，或团队规模/环境变化使跨网恢复成为日常操作。
