## D1 · 技术栈（拍板）

- **WPF**（`net10.0-windows` + `SupportedOSPlatformVersion=10.0.17763.0`），`WinExe`，托盘常驻。
- 托盘图标用 **`Hardcodet.NotifyIcon.Wpf`（MIT）**；若不想引第三方，退化方案是
  `UseWindowsForms=true` + `System.Windows.Forms.NotifyIcon`（同进程内互操作，Win10/Win11 行为一致）。
- **不引入 Windows App SDK / WinUI 3**（会同时抬高 OS 门槛与安装体积，且 Win10 上需额外运行时）。
- 语言/框架约束见 `docs/Win10-Win11-兼容性要求.md`（含可自动化的 4 条静态检查）。

## D2 · 引擎形态与服务化（拍板）

**引擎以 Windows Service 运行，用 `shawl` 作服务包装器**（不是自己 `sc create`）。

| 依据 | 结论 |
|---|---|
| 真机实测（真机结论 §5） | `sc.exe create` 直接包 console 程序 → `Start-Process` 失败（`CouldNotStartService`）：SCM 要服务协议汇报，console 程序不满足 |
| 上游生态 | `Bill-Stewart/SyncthingWindowsSetup` 内部即用 **`shawl.exe`** 跑 Syncthing 服务，另有 `asmt.exe` 管服务账号 |
| 会话独立性 | 实测裸进程会随 SSH 会话结束被杀；计划任务方式在 WinServer-A 上 `LastTaskResult=1` 起不来；**服务/计划任务必须由安装脚本以正确路径注册** |

**服务账号（拍板）**：创建专用本地账号 **`LanSyncSvc`**（非 SYSTEM、非交互登录），授予：
1. "Log on as a service" 权限；
2. 同步目录 **Modify**：`icacls "<dir>" /grant "LanSyncSvc:(OI)(CI)M" /t`；
3. 会随安装程序创建、卸载时禁用（**不删除**账号，避免影响其它软件）。

## D3 · API key 与权限边界（拍板，含权衡说明）

**决定**：API key 存 `%ProgramData%\LanSync\api-key.txt`，ACL = `SYSTEM` + `Administrators` + `LanSyncSvc` 完全控制、
本机 `Users` **只读**；Syncthing GUI 只绑 `127.0.0.1:8384`。

**为什么不让托盘独占**：引擎以服务身份运行、托盘以人类用户身份运行——两者不同账号，
若 key 只给服务账号，托盘就读不到（除非托盘提权，UX 不可接受）。
因此本方案的实际保护边界是：**"防局域网内他人 / 防同机其它非管理员用户"**，
**不防本机管理员**（管理员本来就能读服务配置、也能直接改 Syncthing 配置）。

**可选增强（不阻塞开工）**：用 **DPAPI（machine 作用域）** 加密 key 文件内容，解密的机器范围不变，
收益是"文件被复制到别的机器也解不开"；代价是多一层依赖与排障成本。tzgj 线可先按明文+ACL 落地，留 TODO。

> 这条与 PRD §FR-5.4 的"凭证不落明文"存在**局部让步**，需在 PRD 里如实标注（第二批文档更新时处理）。

## D4 · 安装包（拍板）

**Inno Setup**（单文件 `.exe`），安装内容与步骤固定为：

1. 校验并落地 `syncthing.exe`（**SHA-256 固定值校验**，v2.1.5 `/36a0f7bc…f50344`，与真机实验一致）；
2. 落地 `shawl.exe` + 托盘程序（`LanSync.Tray.exe`）；
3. 创建 `LanSyncSvc` 账号 → 授予 "作为服务登录" → 注册服务（shawl 包 `syncthing.exe serve --home …`）；
4. 生成 API key + 写配置文件（ACL 按 D3）；
5. 交互询问同步目录 → `icacls` 授权 → 起服务 → 托盘加开机自启（HKCU `Run`）；
6. **卸载**：停服务 → 删服务 → 禁账号 → 删程序与配置 → **绝不删除任何用户同步目录**（PRD §6.9）。

**静默安装**：支持 `/SILENT` 与 `/DIR=`、`/SYNCDIR=` 参数（便于自己人批量装）。
**代码签名**：安装包与两个 exe 都需签名；证书来源属**待项目发起人决策项**（R10 的 P0），未签名前只在自己机器上试装。

## D5 · 托盘 ↔ Adapter 的接口边界（拍板）

- 托盘**只调用 `LanSync.Syncthing` 暴露的方法**，**禁止**自己发 Syncthing REST 请求（否则授权/错误处理会双份）。
- 当前可用能力（迭代 1 已实现并通过复核）：`HealthAsync`、`Get/SaveConfigurationAsync`（安全 GET→改→PUT）、
  `Add/RemoveDeviceAsync`、`Add/UpdateFolderAsync`、`Get/SetIgnoresAsync`、`GetConnectionsAsync`
  （映射为 `ConnectionKind.Direct/Relay/Offline/Unknown` + paused）、`SubscribeEventsAsync`、
  `Pause/ResumeAsync`、`GetFolderErrorsAsync`（**只读**，不做清理）。
- **本迭代不可用**（等 codex 迭代 2）：版本恢复事务（`pause(对端)→restore→判空→finally resume`）。
  ⇒ 托盘的"历史版本"入口**先做只读列表**，恢复按钮先禁用/或留到 C7 完成后接通。
- 状态灯映射（唯一允许的"解释"）：`Direct→绿`、`Relay→黄`、`Offline→红`、授权类异常（阶段二）→橙。
