1. 选型：WPF（不是 WinForms）

决定：托盘壳用 WPF，目标框架 net10.0-windows，最低 OS 10.0.17763.0（Win10 1809）。

依据 - PRD 附录 F 与 FR-6.8 指定的参考实现是 GermanCoding/SyncTrayzor（续维护版，MIT，C#），其本身就是 WPF。 - 托盘要呈现的都不是"表单"：状态灯 + 同步进度/速率 + 冲突列表（需翻译后的友好文案）+ 恢复面板（列版本、选择、恢复）。这类列表/模板/数据绑定用 WPF 明显更省事，WinForms 会写成大量手工布局代码。

2. 托盘图标实现：同工程启用 WinForms 的 NotifyIcon，阶段一不引第三方包

决定：LanSync.Tray.csproj 同时设 UseWPF=true 与 UseWindowsForms=true，托盘图标用 System.Windows.Forms.NotifyIcon + ContextMenuStrip。

依据：NotifyIcon 由 Windows Desktop SDK 内置，零 NuGet 依赖——实现机网络受限（读不到 GitHub），引 Hardcodet.NotifyIcon.Wpf 之类社区库会引入还原风险。若后续确需气泡通知/现代菜单，再单独评估切库（记入 P2，不阻塞骨架）。

3. 状态灯语义（权威口径，纠正"三色 / 四色"的分歧）

PRD 里两处口径不同，以本 ADR 为准：

来源 表述 归属
§6.1.1 职责 4 绿=直连 / 黄=中继 / 红=离线（Adapter 只提供这三态） 阶段一
§6.4 四色：绿/黄/红 + 橙=授权异常 橙属阶段二（授权系统阶段一明确不做）

阶段一实现四态：绿=直连、黄=中继、红=离线、灰=已暂停（本地暂停态，由 pause/resume 决定，不需要授权信息）。 橙=授权异常只在枚举里留色位，阶段一不取值、不显示。

4. 进程边界与 IPC：阶段一不引入自定义 IPC

决定 - 引擎（syncthing.exe）以 Windows Service 身份运行；托盘假设"引擎服务已在跑、REST 在 127.0.0.1:8384"。 服务包装器 = shawl（依据：① 真机实测 sc.exe create 直接包 console 程序 → Start-Service 失败 CouldNotStartService； ② 上游 Bill-Stewart/SyncthingWindowsSetup 内部即用 shawl.exe，并用 asmt.exe 管服务账号）。落地归属见 §9 owner 表。 - 托盘进程内直接引用 LanSync.Syncthing 库调 REST，不自己起后台常驻、不发明命名管道/套接字协议。 - 托盘进程只做状态与配置，不持有文件句柄（PRD §6.9 P0）。

触发条件：将来若 Adapter 需要常驻进程（后台守护、跨用户会话访问），再单开 ADR-002 引入 IPC —— 现在做属于过度设计。

5. 配置与密钥位置

内容 位置 权限/纪律
引擎 home、引擎 config、引擎 API key %ProgramData%\LanSync\api-key.txt 安装器创建；ACL：SYSTEM+Administrators+服务账号完全控制、本机 Users 只读（托盘是普通用户进程，必须能读）。不得写日志、不得进仓库、不得进公开文档
用户级设置（窗口位置、上次页签） %LOCALAPPDATA%\LanSync\settings.json 普通用户可写
日志 %ProgramData%\LanSync\logs\（引擎）+ 托盘自身日志同目录 与引擎统一，便于支持排障

6. 骨架范围（tzgj 线第一批交付）

  1. src/LanSync.Tray/LanSync.Tray.csproj：net10.0-windows；UseWPF；UseWindowsForms；SupportedOSPlatformVersion=10.0.17763.0；引用 LanSync.Syncthing、LanSync.Core；加进 LanSync.sln
  2. 主窗最小骨架：连接状态区（四态灯）、文件夹列表、暂停/恢复按钮占位、"冲突"页签占位、"恢复版本"面板占位
  3. NotifyIcon + 上下文菜单（打开主窗 / 退出）
  4. 状态来源接 Adapter（LanSync.Syncthing）：连接类型 → 灯色；/rest/folder/errors → 冲突页签数据源
  5. 不实现：授权相关（橙）、自动更新、代码签名、真正的恢复写操作（面板先只读展示）

不含（别的线负责）：引擎 Service 注册（codex 线）、安装器/长路径 manifest/PS 5.1 脚本骨架（tzgj 线第二批）

7. 约束与验收

  • 禁止 Win11 专有组件（WindowsAppSDK、Mica、SnapLayout 等）；目标 Win10 1809 起
  • .ps1 含非 ASCII 必须带 UTF-8 BOM；用 PowerShell 5.1 语法
  • Directory.Build.props 已开 TreatWarningsAsErrors：构建零警告
  • 骨架验收：dotnet build LanSync.sln + dotnet format LanSync.sln --verify-no-changes 通过（功能完整度不要求）

8. 实现机环境前提（写给实现方）

  • 需要 .NET SDK 10.0.401（global.json 钉 10.0.401 + rollForward: latestPatch → 必须落在 10.0.4xx 带内；截至 2026-09-15，10.0.4xx 只有 10.0.400 与 10.0.401）
  • Linux CI 注意：托盘工程是 net10.0-windows，跨平台 job 只跑 LanSync.Core / LanSync.Syncthing / 两个测试工程；全 sln 构建放 Windows job（需要时加 EnableWindowsTargeting）——CI 侧由主线落地，实现方不必处理

9. 引擎服务化细节（安装器落地用）

项 决定
包装器 shawl.exe（MIT），包 syncthing.exe serve --home %ProgramData%\LanSync\engine …
服务名 / 账号 服务名 LanSyncEngine；专用本地账号 LanSyncSvc（非 SYSTEM、非交互登录）
账号权限 ① "Log on as a service"；② 同步目录 Modify：icacls "<dir>" /grant "LanSyncSvc:(OI)(CI)M" /t；③ 卸载时禁用不删除账号
依赖安装 安装器需检测 .NET Desktop Runtime 与 VC 运行库；缺失时提示并提供离线包路径
失败可见性 服务启动失败必须写入 %ProgramData%\LanSync\logs\install.log 并在安装器末尾显式提示（不能静默失败）

排障锚点：真机实验里"裸进程随 SSH 会话被杀""计划任务 LastTaskResult=1 起不来"两类失败都记录在 docs/M0.5-真机实验结论（Windows+跨网）.md。

10. 安装包与安装/卸载步骤（Inno Setup）

形态：单文件 .exe（Inno Setup），支持 /SILENT、/DIR=、/SYNCDIR=。

  1. 校验并落地 syncthing.exe（SHA-256 固定比对：v2.1.5 = 36a0f7bc…f50344）；落地 shawl.exe 与 LanSync.Tray.exe
  2. 创建 LanSyncSvc → 授予"作为服务登录" → 用 shawl 注册服务（参数见 §9）
  3. 生成 API key + 写配置（ACL 按 §5）
  4. 交互询问同步目录 → icacls 授权 → 起服务 → 托盘加开机自启（HKCU Run）
  5. 卸载：停服务 → 删服务 → 禁账号 → 删程序与配置 → 绝不删除任何用户同步目录（PRD §6.9）
  6. 代码签名：安装包与两个 exe 都需签名；证书来源属待项目发起人决策项（R10 的 P0），未签名前只在自己机器试装

11. 托盘 ↔ Adapter 接口边界

  • 托盘只调用 LanSync.Syncthing 暴露的方法，禁止自己发 Syncthing REST 请求（否则错误处理与授权口径会双份）。
  • 迭代 1 已具备（且通过零改动复核）：HealthAsync、配置安全更新（GET→改→PUT）、设备/文件夹/忽略规则、GetConnectionsAsync （映射 ConnectionKind.Direct/Relay/Offline/Unknown + paused）、SubscribeEventsAsync、Pause/ResumeAsync、GetFolderErrorsAsync（只读）。
  • 尚不可用（等 codex 线迭代 2 的 C7）：版本恢复事务。⇒ 托盘"恢复版本"面板先只读展示，"恢复"按钮禁用或留空实现。
  • 状态灯映射见 §3（四态 + 橙留位）。
