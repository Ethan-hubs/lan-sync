## 3. 本轮实验改掉了 8 个"文档里的错误假设"

这些全部已落进手册 v0.3 与 G1 契约（附变更记录）：

| # | 原以为 | 实测结论 | 影响 |
|---|---|---|---|
| 1 | relay 的 ID/URI 都不打印 | **URI 默认就打印**（源码 `main.go:270` 无条件）；只有 `ID:` 行在 `if debug` 内 | 取 ID 的步骤简化：默认日志的 URI 里已含 `id=`，追加 `&token=` 即可 |
| 2 | `bytesProxied` 双向 ⇒ 成本要 ÷2（否则高估 2 倍） | **错**。实测 8 MiB 文件 → `bytesProxied` +8,414,742 B = **8.02 MiB（1.00×）**；A 侧 `outBytesTotal` +8.00 MiB | 成本口径 = `bytesProxied × 单价`；倍数来自**接收端数量**，不是 2 |
| 3 | 强制走 relay 只需改对端地址 | **不够**：还需 ① `relaysEnabled=true`（置 false 时 relay listen 地址**完全不生效**）② 去掉直连 listen ③ **主动重启**（已建立的直连不会因地址变更而断） | E4-B 步骤补全 |
| 4 | 恢复 API 调了就生效 | **不暂停对端 = 静默失效**：对端较新版本 1–2 秒内覆盖回去，而 API 返回成功（空字典） | 恢复必须 `pause(对端) → restore → resume`；UI 要提示"会覆盖对端当前版本" |
| 5 | `versioning.params` 可以传数字 | 必须**字符串**：`{"maxAge": "2592000"}`；传数字 → `HTTP 400 cannot unmarshal number ... of type string` | 生成配置的类型正确性 |
| 8 | `maxAge = 30` 就是 30 天（2026-09-13 追加） | **错，单位是秒**：staggered 版式器按秒解析（源码 `lib/versioner/staggered.go:39`，默认 31536000＝1 年），参考实现一度直接传天数 | 保留 30 天必须写 `"2592000"`；已在 G1 F11 / M0.5 手册 / PRD 勘误1 / 参考实现中更正 |
| 6 | `stdiscosrv -version` 可用 | v2 用 kong，`-version` 会被拆成 `-v -e ...` 报错；查版本用 `-v` | 手册命令修正 |
| 7 | `/rest/folder/versions` 返回即可信 | 返回体是"每文件一条错误"的字典，**必须判空**；空 = 成功 | Adapter 必须检查返回体，不能只看 HTTP 200 |

## 5. 复现方式

```bash
cd /data/lan-sync/adapter
python3 lab.py up            # 起两个实例、私有化、互加设备、建文件夹（staggered 保留30天＝maxAge 2592000 秒）
python3 lab.py checks        # 9 项契约检查 → local-lab/REPORT.md
python3 exp_restore.py       # 恢复语义两组对照 → local-lab/exp-restore.json
python3 net_lab.py up        # 起 stdiscosrv + 私有 strelaysrv（共享 token）
python3 net_lab.py relay     # 强制 relay-only，验证 relay 路径 + 字节计量
python3 net_lab.py disco     # 自建 discovery + dynamic 地址，验证发现链路
python3 net_lab.py bad-token # 负例：错误 token 应连不上
python3 net_lab.py status / down
```

## 5.1 一条观察（供 E4 参考）

负例测试里 relay 日志的 `invalid token` 计数为 **0**，但错误 token 的实例确实连不上——
说明**拒绝发生在协议早期且没有留下日志**。运维含义：**不能靠翻 relay 日志发现"谁在拿错 token 试"**，
要发现异常得看连接数/流量侧的异常（这也是 W1/W2 想补的能力）。
